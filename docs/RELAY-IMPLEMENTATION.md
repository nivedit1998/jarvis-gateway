# Encrypted relay implementation — M1

One fixed public origin, one administrator-pinned Ubuntu B public key and a dedicated Jarvis-only free Upstash resource. Core token/U private key never enter Gateway. Production environment only; unconfigured previews fail closed. No Vercel CLI.

/api/v1 routes rewrite to api/relay.js with a server-derived logical target. Only fixed POST operations exist; signed request bytes use the logical public path without query strings. Required auth headers: X-Principal-Id, X-Bridge-Id, X-Timestamp, X-Nonce, X-Signature. Phone principal is SHA256(S), bridge principal is SHA256(B). Raw body bytes are signed exactly. Valid high/low-S signatures accepted. Nonces, rates, device scopes and active/pending status are enforced. Provider/body errors never echo secrets or content.

Bridge: /bridge/offer, /bridge/register (pending or active tied to a valid offer), /bridge/revoke, /bridge/poll {device_ids}, /bridge/ack {device_id,message_ids}, /bridge/messages {envelope}, /bridge/wait {}.
Phone: /phone/messages {envelope}, /phone/poll {cursor,max}, /phone/ack {message_ids}.
Bootstrap: unauthenticated /pairing/phone/request {envelope}; then /pairing/{phone|bridge}/{poll|messages|ack}, scoped by offer_id, with pending S signatures allowed only for that offer. Initial sealed Base bootstrap is rate-limited and usable only against B-registered non-consumed offers. Offer ID is not an authentication credential. Pairing packets and keys are those recorded in contracts/jarvis-e2e-v1/ACCEPTANCE.md. Bootstrap poll returns envelopes and corresponding message_ids (initial Base packet transport ID is its SHA256 digest).

A Redis Lua transaction bounds/updates device/offer/queue/replay state atomically. Queues hold envelope bytes and routing metadata only; control has reserved capacity and is selected first. Exact-ID acknowledgements, digest conflict checks and lane/epoch sequence collision checks survive ack/retry. State is limited to 8 paired identities, 4 simultaneous offers, 128 packets per mailbox, 4096 replay outcomes; expired packets/outcomes are pruned. Pairing/account reset is a separate explicit operation, never automatic. No shared in-memory socket registry is assumed.

Idle wakeup: bridge makes a signed bounded /bridge/wait request. Gateway subscribes to the dedicated Redis notification channel, confirms subscription, then checks durable work to close the subscribe/publish race. It waits at most 50 seconds (function maxDuration 60). Phone enqueues publish an opaque wake hint. Wake loss cannot lose the packet: reconnect checks durable work. This avoids continuous one-second idle Redis polls. Redis/Vercel quotas still apply; measure and monitor actual usage before treating the free tier as unlimited. No audio/content in wake notifications.

Tests: 16 Node tests and build checks; explicit live synthetic probe validates atomic racing deduplication, sequence/digest conflicts, ack and nonce replay against the dedicated database. Separate live SUBSCRIBE/PUBLISH test validates wakeup. No plaintext conversational test endpoint exists. A full real-model encrypted product round-trip must pass after deployment before claiming readiness.
